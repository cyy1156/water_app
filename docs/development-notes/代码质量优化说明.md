# 代码质量三项优化说明

针对开发者工具「代码质量」里未通过的三项，按下面方式处理。

---

## 一、启用组件按需注入（已配置）

**状态**：已在 `app.json` 中增加配置。

**配置项**：
```json
"lazyCodeLoading": "requiredComponents"
```

**说明**：小程序启动时只注入当前页面用到的组件和代码，未访问的页面和未使用的组件延后加载，可降低启动耗时和内存。需基础库 2.11.1+。

**你可做的**：重新编译并看「代码质量」里「启用组件按需注入」是否已通过。

---

## 二、主包大小 &lt; 1.5M

**原因**：主包内页面和静态资源过多，总体积超过 1.5M。

**做法**：把**非 TabBar 页面**放到分包里，主包只保留 Tab 页和必要资源。

### 步骤 1：新建分包目录

在项目根目录下新建：

- `packageOther/index/`（对应原 pages/index）
- `packageOther/calendar/`
- `packageOther/points/`
- `packageOther/chat/`
- `packageOther/mall/`

### 步骤 2：移动页面文件

把以下整页目录**移动**到 `packageOther/` 下对应目录（保持原文件名）：

| 原路径 | 目标路径 |
|--------|----------|
| pages/index/* | packageOther/index/* |
| pages/calendar/* | packageOther/calendar/* |
| pages/points/* | packageOther/points/* |
| pages/chat/* | packageOther/chat/* |
| pages/mall/* | packageOther/mall/* |

注意：每个页面里的 `require('../../utils/...')` 需改成 `require('../../../utils/...')`（多一层 `../`）。

### 步骤 3：修改 app.json

把 `app.json` 改成类似下面（只保留主包两个 Tab 页，其余进分包）：

```json
{
  "pages": [
    "pages/home/home",
    "pages/profile/profile"
  ],
  "subpackages": [
    {
      "root": "packageOther",
      "name": "other",
      "pages": [
        "index/index",
        "calendar/calendar",
        "points/points",
        "chat/chat",
        "mall/mall"
      ]
    }
  ],
  "window": { ... },
  "tabBar": { ... },
  "lazyCodeLoading": "requiredComponents"
}
```

### 步骤 4：修改跳转路径

分包后，这些页面的路径变为「分包 root + 页面路径」：

- 日历：`/packageOther/calendar/calendar`
- 其它页同理。

在「我的」页中，把「喝水日历」的入口改为：

```html
<navigator url="/packageOther/calendar/calendar" ...>查看统计 ›</navigator>
```

若有其它 `navigateTo` 或 `navigator` 指向 index/points/chat/mall，也改为 `/packageOther/xxx/xxx`。

完成后重新构建，主包体积会明显下降，一般可满足 &lt; 1.5M。

---

## 三、图片和音频资源 ≤ 200K

**规则**：单张图片或单个音频文件不超过 200KB。

**建议**：

1. **检查大文件**  
   在项目里查找 `images/`、`assets/` 等目录下的 `.png`、`.jpg`、`.mp3`、`.wav` 等，看是否有 &gt; 200KB 的。

2. **压缩图片**  
   - 使用 [TinyPNG](https://tinypng.com/) 或微信开发者工具自带的压缩。  
   - 智能体照片 `images/common/agent.png` 若超过 200K，务必压缩或缩小尺寸（如宽度 400～600px 再导出）。

3. **音频**  
   - 若有背景音、提示音，单文件控制在 200K 内；  
   - 可考虑压缩为 mp3、降低码率或缩短时长。

4. **大资源放云端**  
   - 超过 200K 且必须使用的图/音频，可上传到 CDN 或云存储，运行时用 `wx.downloadFile` 或 `image` 的 `src` 使用 URL，不放进代码包。

改完后在「代码质量」里再看「图片和音频资源大小应不超过 200K」是否通过。

**项目内已做**：已在 `images/README.md` 中注明单文件 200KB 限制与压缩建议，新增或替换图片时请遵守。

---

## 小结

| 项目 | 处理方式 |
|------|----------|
| 组件按需注入 | 已在 app.json 配置 `lazyCodeLoading: "requiredComponents"` |
| 主包 &lt; 1.5M | 按上文把非 Tab 页移到分包并改 app.json、跳转路径 |
| 图片/音频 ≤ 200K | 压缩或缩小尺寸、大文件放 CDN，保证单文件 &lt; 200KB |

按需注入生效后，可先看「代码质量」是否通过；主包和资源两项按上面步骤做完即可一起通过。
