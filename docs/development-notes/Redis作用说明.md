# Redis 在本项目中的作用说明

## 📖 Redis 简介

**Redis**（Remote Dictionary Server）是一个开源的内存数据结构存储系统，可以用作：
- **数据库**：持久化存储
- **缓存**：高速数据缓存
- **消息中间件**：发布/订阅功能

**特点**：
- ⚡ **速度快**：数据存储在内存中，读写速度极快（微秒级）
- 💾 **持久化**：支持数据持久化到磁盘
- 🔄 **数据结构丰富**：支持字符串、列表、集合、哈希表等
- 📈 **高并发**：支持高并发读写

## 🎯 在本项目中的具体作用

### 1. **缓存热点数据，提升性能**

#### 1.1 缓存今日打卡数据

**场景**：用户频繁查看今日打卡情况

**没有 Redis 的情况**：
```
用户请求 → 后端 → 查询数据库 → 返回数据
每次都要查询数据库，响应慢（50-200ms）
```

**使用 Redis 的情况**：
```
第一次请求：用户请求 → 查询数据库 → 存入Redis → 返回数据
后续请求：用户请求 → 从Redis读取 → 返回数据（1-5ms）
```

**代码示例**：
```java
// 获取今日打卡数据
public TodayCheckinVO getTodayCheckin(Long userId) {
    String key = "checkin:today:" + userId + ":" + LocalDate.now();
    
    // 1. 先尝试从Redis获取
    TodayCheckinVO cached = (TodayCheckinVO) redisTemplate.opsForValue().get(key);
    if (cached != null) {
        return cached;  // 直接返回，无需查询数据库
    }
    
    // 2. Redis中没有，查询数据库
    List<CheckinRecord> records = checkinRecordMapper.selectList(...);
    TodayCheckinVO vo = buildVO(records);
    
    // 3. 存入Redis，缓存1小时
    redisTemplate.opsForValue().set(key, vo, 1, TimeUnit.HOURS);
    
    return vo;
}
```

**效果**：
- 第一次查询：50-200ms（查询数据库）
- 后续查询：1-5ms（从Redis读取）
- **性能提升：10-200倍**

#### 1.2 缓存日历数据

**场景**：用户查看打卡日历，需要查询整个月的打卡记录

**缓存策略**：
```java
String key = "checkin:calendar:" + userId + ":" + year + ":" + month;
// 缓存1小时

```

**好处**：

- 缓存后，切换月份时响应更快

#### 1.3 缓存用户信息

**场景**：用户信息在多个接口中频繁使用

**缓存策略**：
```java
String key = "user:info:" + userId;
// 缓存30分钟

```

#### 1.4 缓存商品列表

**场景**：商城商品列表被大量用户访问

**缓存策略**：
```java
String key = "mall:goods:list";
// 缓存1小时
redisTemplate.opsForValue().set(key, goodsList, 1, TimeUnit.HOURS);
```

**好处**：
- 商品列表变化不频繁
- 缓存后减少数据库查询压力

### 2. **减少数据库压力**

**问题**：如果所有请求都直接查询数据库

**影响**：
- 数据库连接数有限（通常20-100个）
- 数据库查询慢（磁盘IO）
- 高并发时数据库可能成为瓶颈

**解决方案**：使用Redis缓存

**效果**：
- 大部分请求从Redis读取，不访问数据库
- 数据库只处理写操作和缓存未命中的读操作
- 数据库压力降低 **80-90%**

**示例**：
```
1000个用户同时查看今日打卡数据

没有Redis：
- 1000次数据库查询
- 数据库压力：1000次/秒

有Redis（假设80%命中率）：
- 800次从Redis读取（1-5ms）
- 200次数据库查询
- 数据库压力：200次/秒
- 压力降低：80%
```

## 🔄 Redis 工作流程

### 读取数据流程

```
1. 用户请求数据
   ↓
2. 检查Redis中是否有缓存
   ↓
   有缓存 → 直接返回（1-5ms）✅
   ↓
   无缓存 → 查询数据库（50-200ms）
   ↓
3. 将查询结果存入Redis
   ↓
4. 返回数据给用户
```

### 写入数据流程

```
1. 用户提交数据
   ↓
2. 保存到数据库
   ↓
3. 更新或删除相关Redis缓存
   ↓
4. 返回成功
```

## 💡 为什么需要 Redis？

### 1. **性能需求**

小程序用户期望：
- 页面加载快（< 200ms）
- 操作响应快（< 100ms）

**没有Redis**：难以达到这个性能要求
**有Redis**：轻松达到，甚至更快

### 2. **成本考虑**

**数据库服务器**：
- 需要高性能硬件
- 成本高

**Redis服务器**：
- 内存存储，成本相对较低
- 可以用较小的服务器承载大量缓存

### 3. **可扩展性**

随着用户增长：
- 数据库压力会越来越大
- Redis可以轻松扩展（集群模式）
- 系统整体性能保持稳定

## ⚠️ 注意事项

### 1. 缓存一致性

**问题**：缓存数据和数据库数据可能不一致

**解决方案**：
- 写操作时更新或删除缓存
- 设置合理的过期时间
- 定期刷新热点数据

### 2. 缓存穿透

**问题**：查询不存在的数据，每次都查数据库

**解决方案**：
- 对空结果也进行缓存（设置较短过期时间）
- 使用布隆过滤器

### 3. 缓存雪崩

**问题**：大量缓存同时过期，导致数据库压力骤增

**解决方案**：
- 设置不同的过期时间（加随机值）
- 使用缓存预热

### 4. 内存管理

**问题**：Redis是内存存储，内存有限

**解决方案**：
- 设置合理的过期时间
- 使用LRU（最近最少使用）淘汰策略
- 监控内存使用情况
