# 使用本地图片方案（解决DNS解析失败问题）

## 🔍 问题原因

`ERR_NAME_NOT_RESOLVED` 表示无法解析域名，说明：
- 外部图片服务（如 placeholder.com、imgur.com）无法访问
- 可能是网络环境限制或DNS问题

## ✅ 解决方案：使用本地图片

### 步骤1：配置后端静态资源服务（已完成）

后端已配置商品图片静态资源服务：
- 配置路径：`backend/src/main/java/com/waterapp/config/WebMvcConfig.java`
- 配置项：`app.goods.upload-dir: uploads/goods`
- 访问路径：`/uploads/goods/图片名.png`（注意：你的后端配置了 `context-path: /api`，所以最终访问是 `/api/uploads/goods/...`）

### 步骤2：创建商品图片目录

在项目根目录创建目录：

```bash
# Windows PowerShell
mkdir backend\uploads\goods

# Linux/Mac
mkdir -p backend/uploads/goods
```

### 步骤3：准备商品图片

将商品图片放到 `backend/uploads/goods/` 目录，例如：
```
backend/uploads/goods/
├── 24efd398deea485189336bf09c24ccba.jpeg~tplv-a9rns2rl98-downsize_watermark_1_5_b.png   # 精美水杯（你当前目录里已存在）
├── book.png                                                                              # 健康手册（你当前目录里已存在）
├── Tshirt.png                                                                            # 定制T恤（你当前目录里已存在，建议后续改为小写 tshirt.png 便于 Linux 部署）
├── watch.png                                                                             # 运动手环（你当前目录里已存在）
├── set.png                                                                               # 水杯套装（你当前目录里已存在）
└── scale.png                                                                             # 健康秤（你当前目录里已存在）
```

**图片要求**：
- 格式：jpg、png、webp
- 尺寸：建议 300x300 或 400x400 像素
- 大小：建议单张不超过 500KB

### 步骤4：更新数据库

执行以下 SQL，使用本地图片路径：

```sql
USE `water_app`;

-- 更新商品图片URL为本地路径（按你当前目录实际文件名填写）
UPDATE `goods` SET `image_url` = '/uploads/goods/24efd398deea485189336bf09c24ccba.jpeg~tplv-a9rns2rl98-downsize_watermark_1_5_b.png' WHERE `name` = '精美水杯';
UPDATE `goods` SET `image_url` = '/uploads/goods/book.png' WHERE `name` = '健康手册';
UPDATE `goods` SET `image_url` = '/uploads/goods/Tshirt.png' WHERE `name` = '定制T恤';
UPDATE `goods` SET `image_url` = '/uploads/goods/watch.png' WHERE `name` = '运动手环';
UPDATE `goods` SET `image_url` = '/uploads/goods/set.png' WHERE `name` = '水杯套装';
UPDATE `goods` SET `image_url` = '/uploads/goods/scale.png' WHERE `name` = '健康秤';

-- 验证更新结果
SELECT `id`, `name`, `image_url` FROM `goods` WHERE `status` = 1 ORDER BY `sort_order`;
```

### 步骤5：重启后端服务

更新配置后，需要重启后端服务：

1. 停止当前运行的后端服务
2. 重新启动后端服务
3. 确保后端服务正常运行

### 步骤6：验证图片显示

1. 在小程序中打开商城页面
2. 检查商品图片是否正常显示
3. 如果图片无法显示，检查：
   - 后端服务是否运行
   - 图片文件是否存在
   - 图片路径是否正确

## 🚀 快速方案：暂时不显示图片

如果暂时没有图片，可以先清空图片URL，显示"暂无图片"占位符：

**执行 SQL**：
```sql
USE `water_app`;

-- 清空所有商品图片URL
UPDATE `goods` SET `image_url` = '' WHERE `image_url` IS NOT NULL;
```

执行后，前端会自动显示"暂无图片"占位符，不会报错。

---

## 📝 图片URL格式说明

### 本地图片路径格式

- **相对路径**：`/uploads/goods/set.png`
  - 前端会自动拼接为：`http://192.168.200.120:8080/api/uploads/goods/set.png`（因为 `apiBaseUrl` 配置为 `http://192.168.200.120:8080/api`）
  
- **绝对路径**：`http://192.168.200.120:8080/api/uploads/goods/set.png`
  - 直接使用，不会拼接

### 前端自动处理

前端代码（`pages/mall/mall.js`）会自动处理：
- 相对路径（`/uploads/...`）→ 自动拼接后端地址
- 绝对路径（`http://...` 或 `https://...`）→ 直接使用
- 空字符串 → 显示"暂无图片"占位符

## 🔧 常见问题

### 问题1：图片无法显示

**检查清单**：
1. ✅ 后端服务是否运行？
2. ✅ 图片文件是否存在？
3. ✅ 图片路径是否正确？
4. ✅ 后端静态资源配置是否正确？

**调试方法**：
- 在浏览器中直接访问：`http://192.168.200.120:8080/api/uploads/goods/set.png`
- 如果能访问，说明后端配置正确
- 如果无法访问，检查后端配置和文件路径

### 问题2：图片路径拼接错误

**原因**：前端 `apiBaseUrl` 配置不正确

**解决方法**：
1. 检查 `app.js` 中的 `apiBaseUrl` 配置
2. 确保格式为：`http://192.168.200.120:8080/api`
3. 前端会把 `/uploads/...` 直接拼到 `apiBaseUrl` 后面（不会去掉 `/api`）

### 问题3：图片太大导致加载慢

**解决方法**：
1. 压缩图片大小（建议单张不超过 500KB）
2. 使用图片压缩工具（如 TinyPNG）
3. 调整图片尺寸（建议 300x300 或 400x400）
