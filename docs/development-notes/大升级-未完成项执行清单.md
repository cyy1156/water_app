## 二、任务 1：GET /ai/persona 接口

### 2.1 目标与验收标准

- **规划出处**：《大升级规划.md》§4.3.5  
- **目标**：提供接口返回「粥粥人设与当前话术」，供前端展示或后续接入 AI 时使用。  
- **验收标准**：  
  - 接口：`GET /ai/persona`，需登录（与现有鉴权一致）。  
  - 返回 JSON 包含：人设简述（名字、语气、风格）、当前占位/推荐话术（可一条或多条）。  
  - 前端可选用其中字段展示在首页聊天卡或设置页。

### 2.2 返回结构建议

```json
{
  "code": 0,
  "data": {
    "name": "粥粥",
    "tone": "可爱、温柔、鼓励型",
    "styleNote": "短句、亲昵称呼，轻拟声词点缀，禁止命令式与责备",
    "placeholder": "今天喝水了吗？💧",
    "phrases": [
      {
        "scene": "GREETING",
        "text": "嗨～我是粥粥🌱 今天也一起把水喝得亮晶晶吧！"
      },
      {
        "scene": "REMIND_SOFT",
        "text": "粥粥轻轻敲敲杯子～咕嘟一口水好吗？💧"
      }
    ]
  }
}
```

- `placeholder`：首页圆环中间聊天卡默认文案。  
- `phrases`：可选，从话术库按场景取 1～2 条，便于「当前话术」展示；若一期不查库，可写死 2～3 条。

### 2.3 实现步骤

#### 步骤 1：确定接口归属

- **建议**：在现有 `AiReminderController` 同包下新增 `AiPersonaController`，或新建 `com.waterapp.controller.AiPersonaController`，单独负责人设与话术，路径前缀 `/ai`。  
- 若希望少改路由，也可在 `AiReminderController` 上增加 `GET /ai/persona`（需保证与 `/ai/reminder/*` 不冲突，例如用 `@GetMapping("/persona")` 且 Controller 映射为 `/ai`）。

#### 步骤 2：新建 Controller

- **文件**：`backend/src/main/java/com/waterapp/controller/AiPersonaController.java`  
- **要点**：  
  - `@RestController`，`@RequestMapping("/ai")`（若与 reminder 共用一个前缀）或 `@RequestMapping("/ai/persona")` 仅此一个方法则用 `/ai`。  
  - 方法：`@GetMapping("/persona")`，从 `HttpServletRequest` 取 `userId`（与现有 `AuthInterceptor` 一致），未登录返回 401。  
  - 调用一个新建的 `PersonaService.getPersona(userId)`（见下），返回 `Result.success(vo)`。

#### 步骤 3：新建 PersonaService 与 VO

- **文件**：  
  - `backend/src/main/java/com/waterapp/service/PersonaService.java`  
  - VO 可定义为内部类或单独 `com.waterapp.vo.PersonaVO`。  
- **逻辑（一期）**：  
  - 固定返回「粥粥」人设：`name`、`tone`、`styleNote`。  
  - `placeholder`：可从 `HomeSummaryVO.tips.chatPlaceholder` 的现有逻辑里复用（用户有自定义则用用户的，否则默认 `"今天喝水了吗？💧"`），或直接写死默认值。  
  - `phrases`：  
    - **方案 A**：写死 2～3 条（如 GREETING、REMIND_SOFT），不查库。  
    - **方案 B**：查 `ai_phrase_template` 表（需先做「任务 2.5」的 Mapper/Entity），按 `scene` 取 `enabled=1` 的记录，每条取 `template` 作为 `text`，可限制条数。

#### 步骤 4：注册鉴权

- 若项目对 `/api/**` 或 `/ai/**` 有白名单，需确认 `/ai/persona` 不在白名单内，走与 `/ai/reminder/settings` 相同的鉴权。

#### 步骤 5：前端对接（可选）

- **文件**：`utils/constants.js` 中已有 `AI_PERSONA: '/ai/persona'`。  
- 在首页或设置页需要展示人设/话术时，调用 `GET /ai/persona`，将 `data.placeholder` 或 `data.phrases` 用于展示；当前首页若已用 `tips.chatPlaceholder` 可保持不变，仅在人设说明处使用本接口。

## 三、任务 2：GET /ai/reminder/preview 接口

### 3.1 目标与验收标准

- **规划出处**：《大升级规划.md》§4.3.5  
- **目标**：在「我的」页粥粥提醒设置区，展示「当前会触发的提醒文案」预览，让用户知道开启提醒后大概会收到什么内容。  
- **验收标准**：  
  - 接口：`GET /ai/reminder/preview`，需登录。  
  - 返回一段可展示的预览文案（或结构化字段，前端拼成一句）。  
  - 逻辑与定时任务「是否发送、文案内容」一致（同一套规则、同一套文案生成）。

### 3.2 返回结构建议

```json
{
  "code": 0,
  "data": {
    "wouldSend": true,
    "reason": "当前在提醒时段内，且距离上次喝水已超过间隔",
    "previewText": "饮水时间到啦，请您记得适量饮水。今日目标 2000ml，上次喝水 30分钟前。",
    "detail": {
      "thing1": "饮水时间到啦,请您记得适量饮水。",
      "thing5": "2000ml",
      "time6": "14:30",
      "phrase4": "30分钟"
    }
  }
}
```

- `wouldSend`：按当前用户设置 + 当前时间 + 今日喝水和上次打卡时间，判断「若此时跑定时任务是否会发」；用于设置页提示「当前会/不会触发提醒」。  
- `previewText`：把订阅消息里的关键信息拼成一句人话，便于直接展示。  
- `detail`：与微信订阅模板字段一致，便于调试或高级展示。

### 3.3 实现步骤

#### 步骤 1：在 ReminderService 中新增预览方法

- **文件**：`backend/src/main/java/com/waterapp/service/ReminderService.java`  
- **方法**：`ReminderPreviewVO getPreview(Long userId)`。  
  - 入参：当前用户 ID。  
  - 逻辑复用与 `ReminderScheduledTask` 一致的判断：  
    1. 取用户 `user_reminder_setting`，若未开启提醒则 `wouldSend=false`，`reason="未开启提醒"`。  
    2. 当前时间是否在 `start_time`～`end_time` 内。  
    3. 是否在 `interval_min` 内已发送过（查 `reminder_log` 最近一条 SENT）。  
    4. 若开启 `quiet_after_target`，今日是否已达标。  
    5. 距离上次打卡是否 ≥ 约 30 分钟（与任务一致）。  
  - 文案生成：与 `ReminderScheduledTask.sendReminder` 中一致：  
    - thing1：固定或从话术库取（当前定时任务为固定「饮水时间到啦,请您记得适量饮水。」）  
    - thing5：`targetWater + "ml"`  
    - time6：当前时间 `HH:mm`  
    - phrase4：根据「上次打卡时间」算「刚刚 / X分钟 / X小时 / X天 / 首次」  
  - 将 thing1、thing5、time6、phrase4 拼成 `previewText`（示例：`"饮水时间到啦，请您记得适量饮水。今日目标 2000ml，上次喝水 30分钟前。"`），并填入 VO。

#### 步骤 2：定义 ReminderPreviewVO

- 可放在 `ReminderService` 内部类，或 `com.waterapp.vo` 下。  
- 字段：`wouldSend`、`reason`、`previewText`、`detail`（含 thing1、thing5、time6、phrase4）。

#### 步骤 3：在 AiReminderController 中增加 GET /preview

- **文件**：`backend/src/main/java/com/waterapp/controller/AiReminderController.java`  
- **方法**：`@GetMapping("/preview")`，取 `userId`，调用 `reminderService.getPreview(userId)`，返回 `Result.success(vo)`。  
- **路径**：当前 Controller 为 `@RequestMapping("/ai/reminder")`，因此完整路径为 `GET /ai/reminder/preview`，与 `constants.js` 中 `AI_REMINDER_PREVIEW` 一致。

#### 步骤 4：前端在「粥粥提醒」区块展示

- **文件**：`pages/profile/profile.js`、`profile.wxml`  
- 在「开启粥粥提醒」开关下方或「提醒间隔」下方增加「预览」区域。  
- `onLoad` 或进入设置时若已开启提醒，调用 `GET /ai/reminder/preview`，将返回的 `previewText` 或 `reason` 展示；若 `wouldSend === false`，可展示「当前不会触发提醒：{reason}」。

### 3.4 涉及文件清单

| 类型 | 路径 |
|------|------|
| 修改 | `backend/src/main/java/com/waterapp/service/ReminderService.java`（新增 getPreview、ReminderPreviewVO） |
| 修改 | `backend/src/main/java/com/waterapp/controller/AiReminderController.java`（新增 GET /preview） |
| 修改 | `pages/profile/profile.js`（请求 preview、setData 预览文案） |
| 修改 | `pages/profile/profile.wxml`（展示预览文案区域） |

### 3.5 与定时任务逻辑复用说明

- 为避免「预览」与「实际发送」不一致，建议将 `ReminderScheduledTask` 中「是否该发」「文案四段」抽成 ReminderService 内可复用方法，例如：  
  - `boolean shouldSendReminder(Long userId, LocalDateTime at)`  
  - `ReminderMessageContent buildReminderContent(Long userId, LocalDateTime at)`  
- `getPreview(userId)` 与定时任务均调用上述方法；预览时 `at = LocalDateTime.now()`。

## 四、任务 3：独立组件（progress-ring / chat-card / quick-checkin / exp-bar / goods-card）

### 4.1 目标与验收标准

- **规划出处**：《大升级规划.md》§3.1「建议新增组件（可选但强烈建议）」

- **验收标准**：

  - 首页/我的页改为引用组件，界面与交互与原有效果一致。  
  - 样式通过 props 或 externalClasses 支持主题色等，不写死色值。

### 4.3 实现步骤（通用）

- 每个组件单独建目录，包含：  
  - `progress-ring.js`：`Component({...})`，properties 如 `progress`（0～1 或 0～100）、`themeColor`、`trackColor`。  
  - `progress-ring.wxml`：与当前首页圆环结构一致（conic-gradient 或 canvas）。  
  - `progress-ring.wxss`：从 `home.wxss` 中抽出与圆环相关样式。  
  - `progress-ring.json`：`{ "component": true }`。  
- 在 `pages/home/home.json` 的 `usingComponents` 中注册，将 `home.wxml` 中对应块替换为 `<progress-ring progress="{{ progress }}" themeColor="{{ theme.primary }}" />` 等。  
- 其他四个组件同理：先抽结构+样式，再定义 properties 和 events（如 `bind:checkin`、`bind:tapCard`），页面只传数据和监听事件。

### 4.4 各组件 properties / events 建议

- **progress-ring**：`progress`（Number）、`themeColor`（String）、`trackColor`（String）、可选 `size`（rpx）。  
- **chat-card**：`text`（String）、`themeColor`（String）；事件：`bind:tap`。  
- **quick-checkin**：`themeColor`（String）、`disabled`（Boolean）；事件：`bind:checkin`（detail: { waterMl }）、`bind:custom`。  
- **exp-bar**：`current`（Number）、`max`（Number）、`themeGradient`（String）。  
- **goods-card**：`goods`（Object，含 pic、name、priceCoin、stock）、`coinEnough`（Boolean）；事件：`bind:buy`。

## 五、任务 4：多级经验阈值配置（growth.level-exp-table）

### 5.1 目标与验收标准

- **规划出处**：《大升级规划.md》§7.1「growth.level-exp-table（或 base + growth 公式）」  
- **目标**：支持多级升级阈值（如 Lv1→2 需 1000，Lv2→3 需 1500），而非当前单级固定 `next-level-exp`。  
- **验收标准**：  
  - 配置中可定义每级所需经验（或 base+growth 公式）。  
  - `GrowthService.nextLevelExp(level)` 根据当前 level 返回下一级所需经验。  
  - 升级与前端展示与现有逻辑兼容。

### 5.2 配置方案建议

**方案 A：列表配置（推荐）**

- 在 `application.yml` 中增加：  
  ```yaml
  growth:
    level-exp-table: [1000, 1500, 2000, 2500, 3000, 3500, 4000, 5000]  # 下标 0 表示 Lv1->2 需要 1000，下标 1 表示 Lv2->3 需要 1500...
  ```  
- 若表长度不足（如 level=10 但表只有 8 个元素），可约定最后一值重复或使用 fallback（如当前 `next-level-exp`）。

**方案 B：公式**

- 例如：`nextExp = base + (level - 1) * growth`，配置 `base: 1000`、`growth: 500`。

### 5.3 实现步骤

#### 步骤 1：扩展 GrowthProperties

- **文件**：`backend/src/main/java/com/waterapp/config/GrowthProperties.java`  
- 新增属性：`List<Integer> levelExpTable`，或 `int base` + `int growth`（若用公式）。  
- 在 `application.yml` 中增加对应配置项。

#### 步骤 2：修改 GrowthService.nextLevelExp(int level)

- **文件**：`backend/src/main/java/com/waterapp/service/GrowthService.java`  
- 若用表：`int index = level - 1`（Lv1 对应下标 0）；若 `index < levelExpTable.size()` 返回 `levelExpTable.get(index)`，否则返回最后一个或当前 `nextLevelExp`。  
- 若用公式：`return base + (level - 1) * growth`。

#### 步骤 3：兼容旧配置

- 若未配置 `level-exp-table`，保留现有行为：`growthProperties.getNextLevelExp()` 单值。

### 5.4 涉及文件清单

| 类型 | 路径 |
|------|------|
| 修改 | `backend/src/main/java/com/waterapp/config/GrowthProperties.java` |
| 修改 | `backend/src/main/resources/application.yml`（增加 level-exp-table 或 base/growth） |
| 修改 | `backend/src/main/java/com/waterapp/service/GrowthService.java`（nextLevelExp 逻辑） |
