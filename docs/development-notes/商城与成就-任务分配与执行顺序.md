# 商城与成就 - 前后端任务分配与执行顺序

> 基于《商城与成就需求文档》拆解，明确前后端职责与实施先后顺序。

---

## 一、执行总览

```
Phase 1: 后端 - 数据模型与基础接口（成就/商城改造/提醒联动）
Phase 2: 后端 - 连续打卡成就计算与兑换联动逻辑
Phase 3: 前端 - 商城页改造（自我奖励展示与兑换）
Phase 4: 前端 - 成就页（双专栏）与兑换后设置提醒
Phase 5: 联调 - 闭环验证
```

---

## 二、Phase 1：后端 - 数据模型与基础接口

**目标**：完成数据库表结构、实体与基础 CRUD 接口，为后续业务逻辑提供支撑。

### 2.1 后端任务

| 序号 | 任务 | 说明 | 产出 |
|------|------|------|------|
| 1.1 | 商城商品改造 | 将 `goods` 表/实体调整为「自我奖励」类型；可增加 `type` 字段（如 SELF_REWARD），去除或弱化 `stock`、`address` 逻辑 | 迁移脚本、Goods 实体调整 |
| 1.2 | 兑换记录改造 | 扩展 `exchange_record`：新增 `reminder_id`（关联提醒）、`executed`（是否已执行）；`status` 可简化为：待执行、已执行 | 迁移脚本、ExchangeRecord 实体 |
| 1.3 | 成就表设计 | 新建 `achievement` 表：id, user_id, type（SYSTEM/REDEEMED）, config_json（连续天数/徽章/金币等）, completed_at, 等 | SQL 迁移、Achievement 实体、Mapper |
| 1.4 | 系统成就配置表（可选） | 新建 `achievement_config`：连续天数、徽章名、金币数、排序 | SQL、AchievementConfig 实体 |
| 1.5 | 提醒与兑换关联 | 扩展 `user_reminder_setting` 或新建「单次提醒」表，支持兑换后创建的提醒，关联 `exchange_record_id` | 表设计、实体、Mapper |

**执行顺序**：1.1 → 1.2 → 1.3 → 1.4 → 1.5（有依赖关系时按此顺序）

### 2.2 前端任务

- **无**（Phase 1 纯后端）

---

## 三、Phase 2：后端 - 业务逻辑

**目标**：实现连续打卡成就计算、兑换自我奖励、兑换后自动创建提醒与成就记录。

### 3.1 后端任务

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| 2.1 | 连续打卡成就计算 | 根据 `checkin_record` 计算用户连续打卡天数；达到 3/5/7/10/14/21/30 天时写入 `achievement`（type=SYSTEM），发放徽章与金币 | Phase 1.3、1.4；CheckinService |
| 2.2 | 商城兑换逻辑改造 | 修改 `StoreService.purchaseGoods`：扣减金币 → 写入 `exchange_record` → 创建提醒（占位）→ 写入 `achievement`（type=REDEEMED） | Phase 1.1、1.2、1.3、1.5 |
| 2.3 | 兑换后提醒创建 | 兑换成功后，调用 ReminderService 创建单次提醒；支持用户传入 `remindTime`（执行时间）；关联 `exchange_record_id` | Phase 1.5、2.2 |
| 2.4 | 成就接口 | 提供 `GET /achievement/list`：返回用户系统成就 + 兑换成就，分专栏或带 type 标识 | Phase 1.3、2.1、2.2 |
| 2.5 | 商城商品列表接口 | 确保 `GET /store/goods/list` 仅返回自我奖励类商品；字段满足前端展示（名称、描述、金币、图片） | Phase 1.1 |
| 2.6 | 兑换接口扩展 | `POST /store/purchase` 请求体增加 `remindTime`（可选）；响应中返回 `reminderId`、`achievementId` | Phase 2.2、2.3 |

**执行顺序**：2.1 可与 2.2 并行准备；2.2 → 2.3 → 2.6；2.4、2.5 在 2.1、2.2 完成后实现。

### 3.2 前端任务

- **无**（Phase 2 纯后端）

---

## 四、Phase 3：前端 - 商城页改造

**目标**：商城页改为展示自我奖励商品，支持兑换并跳转设置提醒。

### 4.1 前端任务

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| 3.1 | 商城列表展示 | 调用 `GET /store/goods/list`，展示自我奖励商品（名称、描述、金币、图片占位） | Phase 2.5 |
| 3.2 | 兑换按钮与弹窗 | 点击兑换 → 弹窗确认 → 调用 `POST /store/purchase`，传入 `goodsId`、可选 `remindTime` | Phase 2.6 |
| 3.3 | 兑换成功反馈 | 兑换成功后提示，引导用户「去设置提醒」或「查看成就」 | Phase 2.6 |
| 3.4 | 文案与占位图 | 将原实物类文案改为自我奖励类；图片占位，后续替换 | - |

**执行顺序**：3.1 → 3.2 → 3.3；3.4 可与 3.1 并行。

### 4.2 后端任务

- **无**（Phase 3 纯前端，依赖 Phase 2 接口）

---

## 五、Phase 4：前端 - 成就页与提醒设置

**目标**：新增或改造成就页，双专栏展示；兑换后支持设置提醒时间。

### 5.1 前端任务

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| 4.1 | 成就页结构 | 新建或改造成就页，顶部/ Tab 区分两个专栏：「我们设定的目标」「自己兑换的东西」 | Phase 2.4 |
| 4.2 | 专栏一：系统成就 | 调用 `GET /achievement/list`，筛选 `type=SYSTEM`；展示徽章、连续天数、金币、达成时间 | Phase 2.4 |
| 4.3 | 专栏二：兑换成就 | 筛选 `type=REDEEMED`；展示兑换内容、兑换时间、是否已执行（如有） | Phase 2.4 |
| 4.4 | 兑换后设置提醒 | 兑换成功弹窗中，增加「设置提醒时间」入口；跳转提醒设置页或弹窗内选择时间，调用提醒相关接口 | Phase 2.3、2.6 |
| 4.5 | 成就页入口 | 在「我的」或 TabBar 中增加成就页入口 | - |

**执行顺序**：4.1 → 4.2、4.3（可并行）→ 4.4；4.5 与 4.1 可并行。

### 5.2 后端任务

- **无**（Phase 4 纯前端，依赖 Phase 2 接口）

---

## 六、Phase 5：联调与闭环验证

**目标**：端到端验证「打卡 → 金币 → 兑换 → 提醒 → 成就」全流程。

### 6.1 联调任务

| 序号 | 任务 | 说明 |
|------|------|------|
| 5.1 | 兑换闭环 | 验证：兑换 → 金币扣减 → 成就列表出现兑换记录 → 提醒列表出现对应提醒 |
| 5.2 | 连续打卡闭环 | 验证：连续 3/5/10 天打卡 → 系统成就自动解锁 → 徽章与金币到账 |
| 5.3 | 提醒送达 | 验证：设置提醒时间后，到点能收到订阅消息（若已配置模板） |
| 5.4 | 异常与边界 | 金币不足、重复兑换、网络异常等处理 |
